### card_id 结构
- 8 位数字
- `card_set_id == int(card_id[:5])`（前 5 位是卡包 ID）
- 第 6 位是职业代码
- 9 个 set：10000=中立(56张) / 10001-10007=七职业(各 76-142 张) / **10008=扩展包(78张，跨 7 个职业，按 card_id[5] 区分)**

## 关键发现：card_id 编码
- 8 位数字
- 编码：`[0]='1' [1]='0' [2]=职业 [3]=子包 [4-7]=编号`
- **职业代码位是 [2]**（不是 [3]）：
  - 100xxxxx (set 10000) = 中立
  - 101xxxxx (set 10001) = 森林
  - 102xxxxx (set 10002) = 剑
  - 103xxxxx (set 10003) = 龙（巫师）
  - 104xxxxx (set 10004) = 龙（龙族）
  - 105xxxxx (set 10005) = 死
  - 106xxxxx (set 10006) = 主教
  - 107xxxxx (set 10007) = 魂
  - 108xxxxx (set 10008) = 第8包，**[2]='8' 不在 0-7 范围**——这些卡实际是"跨职业联动包/扩展包"，职业归属不明
- **card_set_id 与职业代码位无直接对应**：card_set_id 是另一维度的卡包分类
- set 10008 的 78 张卡目前归为"中立"（因 [2]='8' 不在映射表内）

## 已完成代码改动
- `_cache.py`：
  - 移除 GitHub EN 数据源，改用本地 `cards_cn_translated.json`
  - 用 asyncio.run_in_executor 在线程池中读文件，不阻塞事件循环
  - 字段标准化：card_id → id（8位补0）；clan 从 card_set_id+card_id 推断；type 1-4 → 中文
  - 新增 `skill_has_kana` 标记（检测 skill_text 是否含日文假名）
  - 名称索引同时索引中文名和日文名（用于跨语种搜索）
- `_formatter.py`：
  - 标签处理改为大小写不敏感
  - 保留原始【...】段落标记（用户翻译时加的），只移除 HTML 风格标签
  - `<ev>/<sev>` 替换为 `\n↳ 进化时：` / `\n↳ 超进化时：`
  - `<ridx=N>` 改为只删除标签（保留内部（1）（2））
  - skill_has_kana 时附【日文】原文
  - 不显示 flavour_text
- `_searcher.py`：
  - 搜索匹配：中文名(100)>日文名(95)>中文名前缀(80)>中文名包含(60)>日文名包含(55)>技能中文(30)>技能日文(28)>类型(10)
  - 职业过滤用 class_code 直接匹配，支持中英文别名
- `_handler.py`：
  - 命令前缀正则改为强制要求命令名后有空白，避免 sv_reload 被误判
  - 帮助文本更新
- `__init__.py`：更新数据源说明
